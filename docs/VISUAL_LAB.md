# Visual Lab: Problems You Can See

A visual lesson is strongest when you can follow how the picture came to be: what was requested or computed, which technology shaped it, and how the result was checked.

The pictures below are entry points. Each one links to its source, problem, and evidence. A rendered image by itself does not prove the behavior or data that produced it.

## How to read a visual lesson

```mermaid
flowchart LR
    Q["Ask a real question"] --> D["Define data and rules"]
    D --> R["Run the responsible system"]
    R --> V["Render what it produced"]
    V --> E["Check the picture against evidence"]
    classDef step fill:#14283b,stroke:#49677d,color:#eef6ff,stroke-width:2px
    classDef focus fill:#123e43,stroke:#66e0be,color:#f3fffc,stroke-width:4px
    class Q,D,R,V step
    class E focus
```

**Diagram status:** authored learning progression, not a runtime architecture or captured execution.

## A scene the eye can follow

[![GUI.SVG fox and sheepdog scene on a ten-by-ten grid](https://raw.githubusercontent.com/TrentBest/TheSingularityWorkshop.GUI/development/docs/assets/fox-sheepdog-10x10.svg)](https://github.com/TrentBest/TheSingularityWorkshop.GUI/blob/development/samples/FoxSheepdogPlane/Program.cs)

**Question:** how do multiple routes and repeated grid cells make an encounter easier to inspect?

**Look for:** the regular isometric plane, scattered dogs, crossing fox routes, and a jump arc.

**Evidence boundary:** GUI.SVG produces this scene from a semantic GUI tree, but the route motion is authored SVG animation. It is not yet an FSM_API-driven execution trace. See the [scene source](https://github.com/TrentBest/TheSingularityWorkshop.GUI/blob/development/samples/FoxSheepdogPlane/Program.cs) and [SVG adapter contract](https://github.com/TrentBest/TheSingularityWorkshop.GUI/blob/development/docs/SVG_ADAPTER.md).

## Make vector geometry and its limits visible

[![Generated GUI.SVG gallery with vector geometry, definitions, filters, and a moving star](https://raw.githubusercontent.com/TrentBest/TheSingularityWorkshop.GUI/development/docs/assets/svg-adapter-gallery.svg)](https://github.com/TrentBest/TheSingularityWorkshop.GUI/blob/development/docs/SVG_ADAPTER.md)

**Question:** can a semantic scene become a useful standalone SVG, and what should the learner inspect when it does?

**Look for:** reused definitions, paths, clipping, filters, and declarative motion. The GUI.SVG guide says this checked-in gallery is regenerated by a sample and compared byte-for-byte in CI.

**Boundary:** SVG features are interpreted by the viewing software. A moving star is not an FSM clock, a GPU renderer, or proof of an interactive application.

## Keep motion inside its bounds

**Question:** how do you make a value reverse at its endpoints instead of wrapping or escaping the allowed range?

Follow [From Problem to Proof](PROBLEM_TO_PROOF.md). It shows the bounded oscillator's states, expected trace, edge cases, and GUI.SVG snapshot. The [upstream recipe](https://github.com/TrentBest/TheSingularityWorkshop.GUI/blob/development/samples/demonstrations/recipes/07-fsm-driven-oscillator.md) says the sample checks FSM_API transitions, oversized steps, invalid configuration, and SVG structure; it links to a visually reviewed CI artifact.

## Plot a function and compare its transformations

**Question:** what changes when a function is shifted vertically, shifted horizontally, or reflected/scaled?

The [coordinate and function recipe](https://github.com/TrentBest/TheSingularityWorkshop.GUI/blob/development/samples/demonstrations/recipes/02-coordinate-functions.md) calculates the base curve and transformed values from the same 33 x-samples, then uses GUI.SVG to render them. CI checks the SVG/XML structure and formulas. The recipe currently says a human visual review is still outstanding, so treat the artifact as structurally checked rather than visually signed off.

## Explore determinism and scale

- **Spread a seeded set of points:** [Physics-seeded point set recipe](https://github.com/TrentBest/TheSingularityWorkshop.GUI/blob/development/samples/demonstrations/recipes/05-seeded-point-set.md). Learn why every marker should map back to the stored seed and point coordinates.
- **Compare an overview and a detail window:** [Mandelbrot field recipe](https://github.com/TrentBest/TheSingularityWorkshop.GUI/blob/development/samples/demonstrations/recipes/06-mandelbrot-field.md). Physics computes and records the escape-time classifications; GUI.SVG consumes the records. The recipe describes a command-line workflow, not an interactive explorer.

## Suggested progression

1. Start with a vector scene and learn which pieces are semantic data.
2. Plot a sampled function and compare how parameters change coordinates.
3. Model a bounded behavior as state and transitions.
4. Carry recorded Physics data across a JSON boundary.
5. Scale the same provenance discipline to a point set or a parameterized field.

Browse the [GUI.SVG recipe gallery](https://github.com/TrentBest/TheSingularityWorkshop.GUI/blob/development/samples/demonstrations/GALLERY.md) for the package-by-package examples. Follow each recipe for exact setup, code, source revisions, and evidence.
